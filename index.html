The V-and-E habit

Graph costs are written in two variables. A dense graph has E = Θ(V²); a sparse graph has E = Θ(V). "O(V + E)" and "O(E log V)" mean very different things in each regime.

Graph Foundations & Representations

The formal model, a working taxonomy, and the two data structures on which every later cost in this module depends.

Definitions      Taxonomy      Degree & paths      Matrix vs list
5
Graph foundations
A graph is a set of vertices and a set of edges
  • Definition - G = (V, E) where V is a finite vertex set and E ⊆ V × V a set of edges. |V| = n, |E| = m.
  • Undirected - edges are unordered pairs {u, v}; the adjacency relation is symmetric.
  • Directed (digraph) - edges are ordered pairs (u, v); u → v does not imply v → u.
  • Weighted - a function w : E → ℝ attaches a cost to each edge.
  • Simple graph - no self-loops, no parallel edges. Our default unless stated.
  • Incidence & adjacency - edge {u,v} is incident on u and v, which are adjacent.

Vocabulary is load-bearing

Every proof today is phrased in vertices, edges, cuts and paths. Sloppiness about ordered vs unordered pairs is the single most common source of errors in directed algorithms later in the module.

Graph foundations
A working taxonomy: know which graph you are holding
  • Directed vs undirected - whether edges carry orientation.
  • Weighted vs unweighted - BFS needs unweighted; Dijkstra needs non-negative weights.
  • Connected vs disconnected - else the graph splits into connected components.
  • Cyclic vs acyclic - a DAG has no directed cycle: the shape of every computation graph.
  • Tree - connected and acyclic; exactly n − 1 edges. The maximally sparse connected graph.
  • Bipartite - V splits into two independent sets; models users × items.
  • Complete graph / clique - every pair adjacent; Kn has n(n−1)/2 edges.

Classification precedes algorithm choice

An algorithm's correctness assumes a graph class. Topological sort requires a DAG; Dijkstra requires non-negative weights; MST requires a connected weighted undirected graph. Classifying the input silently determines which tools are even legal.

Placement tip

"Is it a DAG?" and "is it bipartite?" are single-traversal checks (DFS back-edge test; BFS 2-colouring). Interviewers use them to test whether you reach for traversal reflexively rather than inventing machinery.

Graph foundations
Degree and the handshaking lemma
  • Degree - deg(v) = number of edges incident on v (undirected).
  • In / out degree - for digraphs, incoming and outgoing edges counted separately.
  • Average degree - 2|E| / |V|; constant for sparse graphs, Θ(V) for dense ones.
  • Corollary - the number of odd-degree vertices is always even.
∑v∈V deg(v)=2|E|
Handshaking lemma

Proof (double counting)

Count the set of incidence pairs (v, e) with v an endpoint of e, in two ways.

Summing over vertices gives Σ deg(v). Summing over edges gives 2|E|, because each edge has exactly two endpoints. The two counts enumerate the same finite set, hence they are equal. ∎

The corollary follows because 2|E| is even, so the odd-degree terms must pair up.

Why it matters

This is the prototype of the counting arguments used throughout graph theory, and it is what bounds adjacency-list traversal: Σ deg(v) = 2|E| is exactly why scanning all adjacency lists costs Θ(V + E), not Θ(V·E).

Graph foundations
Paths, cycles, connectivity and components
  • Walk - any alternating sequence of vertices and edges.
  • Path - a walk with no repeated vertex (a simple path).
  • Cycle - a closed walk; a simple cycle repeats only its endpoint.
  • Connected - a path exists between every pair of vertices.
  • Connected component - a maximal connected subgraph. Traversal from v discovers exactly v's component.
  • Strongly connected - in a digraph, directed paths exist both ways for every pair.
  • Distance d(u,v) - the least number of edges on a u–v path; ∞ if unreachable.

These are what algorithms return

BFS and DFS are machines for discovering paths, cycles and components. Naming them precisely lets us state exactly what each traversal guarantees — and what it does not.

Note that d(u,v) is defined by edge count. Once edges carry weights the definition changes and BFS is no longer correct; that is Dijkstra's territory in Part 2.

Common confusion

Walk ⊃ trail (no repeated edge) ⊃ path (no repeated vertex). Cycle-detection proofs break if you conflate them. State which object you mean.

Placement tip

State your representation before you state your complexity. "BFS is O(V+E)" is only true on an adjacency list — on a matrix it is Θ(V²). Interviewers listen for this.

Which to choose

Sparse (E ≈ V) — the common case in AI, social and road networks — favours the list: linear space and neighbour scans proportional to degree.

Dense (E ≈ V²), or workloads dominated by "is there an edge?" queries, favours the matrix: O(1) lookup, contiguous memory, and direct compatibility with BLAS/GPU kernels.

The matrix view is also what makes Part 4 possible: the Laplacian L = D − A is a matrix, so spectral graph theory necessarily lives in this representation.

Graph foundations
Representing a graph in Python
  • Adjacency list - a defaultdict(list) of (neighbour, weight) tuples; Pythonic and sparse-optimal.
  • One flag - the second append is the only difference between directed and undirected.
  • Matrix - a NumPy array when you need O(1) edge tests or linear algebra.
  • Memory - lists hold ~Θ(V+E) references; the matrix commits Θ(V²) regardless of E.
Engineering note

For graphs beyond ~10⁶ edges prefer a CSR (compressed sparse row) layout — scipy.sparse.csr_matrix — which gives adjacency-list asymptotics with matrix-grade cache locality. This is what DGL and PyTorch Geometric use internally.

from collections import defaultdict

class Graph:
    """Undirected weighted graph, adjacency list."""
    def __init__(self, directed=False):
        self.adj = defaultdict(list)   # v -> [(nbr, w)]
        self.directed = directed

    def add_edge(self, u, v, w=1):
        self.adj[u].append((v, w))
        if not self.directed:
            self.adj[v].append((u, w))  # O(1) amortised

    def neighbours(self, u):
        return self.adj[u]          # O(deg u)

    def __len__(self):
        return len(self.adj)

Graph Traversal: BFS & DFS

Two disciplined ways to visit every vertex exactly once — and the foundation of almost every graph algorithm in the remaining three parts.

Generic template      BFS      DFS      Edge classes      Applications
12
Traversal
One template, two behaviours
  • Goal - systematically visit every vertex reachable from a source, exactly once.
  • Two ingredients - a visited set, and a frontier of discovered-but-unexplored vertices.
  • The only difference - BFS's frontier is a FIFO queue; DFS's is a LIFO stack (explicit or the call stack).
  • Why visited is mandatory - graphs contain cycles; without marking, traversal never terminates. Trees needed no such set.
  • Cost - each vertex dequeued once, each adjacency list scanned once ⇒ Θ(V + E).
T(n)= ∑v∈V (1+deg(v)) =V+2E=Θ(V+E)
the handshaking lemma is what collapses the sum

The unification worth remembering

BFS and DFS are the same algorithm with different frontier data structures. Swap the queue for a stack and breadth becomes depth.

This mirrors the stack/queue duality seen in tree traversal: level-order is BFS, pre-order is DFS. Graphs simply add the visited set.

Placement tip

If you can write one generic explore(frontier) and instantiate both, you demonstrate structural understanding rather than memorised code. Interviewers reward that framing.

Traversal
BFS explores in layers — and provably finds shortest paths
  • Strategy - visit the source, then all neighbours, then their neighbours: a wavefront.
  • Theorem - for unit-weight graphs BFS sets dist[v] = d(s, v) for every reachable v.
  • Queue invariant - the queue holds vertices of at most two consecutive distances, in non-decreasing order.
  • Also yields - a BFS tree, connected components, and a bipartiteness test by level parity.
d(s,v)= minu∈N(v) {d(s,u)+1}

Proof by induction on k = d(s,v)

Base. dist[s] = 0 = d(s,s).

Step. Assume every vertex at distance ≤ k is dequeued with a correct label before any vertex at distance k+1. Let d(s,v) = k+1. Some neighbour u has d(s,u) = k, so when u is dequeued v is either already labelled (with ≤ k+1) or is labelled k+1 then. It cannot be labelled less than k+1, else a shorter path would exist. Hence dist[v] = k+1. ∎

Where it fails

With weights, a two-hop cheap path can beat a one-hop expensive edge. BFS's layer argument collapses — the fix is a priority queue, i.e. Dijkstra (Part 2).

Traversal
BFS in Python, and its complexity
  • deque - O(1) append and popleft; a Python list's pop(0) is O(n) and would make BFS O(V²).
  • Mark on enqueue - not on dequeue. Marking late lets a vertex enter the queue many times and destroys the linear bound.
  • Parent map - reconstructs the actual shortest path, not just its length.
  • Time - Θ(V + E). Space - O(V) for queue, dist and parent.
Placement tip

Multi-source BFS: seed the queue with all sources at distance 0. Solves "nearest exit / rotting oranges / 0-1 matrix" problems in one pass instead of |S| passes.

from collections import deque

def bfs(g, src):
    """Unit-weight shortest paths. Theta(V + E)."""
    dist   = {src: 0}
    parent = {src: None}
    q = deque([src])

    while q:
        u = q.popleft()                # FIFO -> layers
        for v, _ in g.neighbours(u):
            if v not in dist:        # first sighting
                dist[v]   = dist[u] + 1
                parent[v] = u
                q.append(v)            # mark on ENQUEUE
    return dist, parent

def path(parent, v):
    """Reconstruct s -> v in O(len(path))."""
    out = []
    while v is not None:
        out.append(v); v = parent[v]
    return out[::-1]

Traversal
DFS dives deep, backtracks, and timestamps everything
  • Strategy - from v, recurse into an unvisited neighbour before considering the rest; back up when stuck.
  • Timestamps - d[v] when first discovered, f[v] when its subtree finishes.
  • Parenthesis theorem - the intervals (d[u], f[u]) and (d[v], f[v]) are either disjoint or properly nested; nesting ⟺ ancestry in the DFS forest.
  • White-path theorem - v is a descendant of u iff, at time d[u], there is a path u ⇝ v of entirely undiscovered vertices.
  • Cost - Θ(V + E) time, O(V) stack depth.

Depth reveals what breadth cannot

DFS gives no distance guarantee, but its finish-time ordering exposes cycles, topological order and strongly connected components — structural facts that layered BFS is blind to.

The reverse of DFS finish order is a topological sort, which is precisely how a computation graph is evaluated and differentiated.

d[u] < d[v] < f[v] < f[u]   ⟺   v is a descendant of u

Traversal
DFS in Python: recursive and iterative
  • Recursive - reads like the definition, but CPython's ~1000-frame limit overflows on deep graphs.
  • Iterative - an explicit stack removes the ceiling; check visited on pop, since a vertex may be pushed more than once.
  • Timestamps - a global clock records d[] and f[] for structural analysis.
  • Time - Θ(V + E). Space - O(V).
Placement tip

Always mention sys.setrecursionlimit is a band-aid, not a fix — and that the iterative form is what production code ships. It is a cheap signal of engineering maturity.

def dfs_rec(g, u, seen=None, clock=None, d=None, f=None):
    """Recursive DFS with discovery/finish times."""
    if seen is None:
        seen, clock, d, f = set(), [0], {}, {}
    seen.add(u); clock[0] += 1; d[u] = clock[0]
    for v, _ in g.neighbours(u):
        if v not in seen:
            dfs_rec(g, v, seen, clock, d, f)
    clock[0] += 1; f[u] = clock[0]     # subtree done
    return d, f

def dfs_iter(g, src):
    """Iterative DFS - no recursion ceiling."""
    seen, stack = set(), [src]
    order = []
    while stack:
        u = stack.pop()                # LIFO -> depth
        if u in seen:                 # check on POP
            continue
        seen.add(u); order.append(u)
        for v, _ in reversed(g.neighbours(u)):
            if v not in seen:
                stack.append(v)
    return order

A back edge exists ⟺ the graph has a cycle. Therefore a single Θ(V+E) DFS simultaneously detects cycles, certifies a DAG, and produces a topological order — no extra work.

DFS applications — and the bridge to backpropagation
  • Cycle detection - a back edge; O(V+E).
  • Topological sort - vertices in decreasing finish time; valid iff the graph is a DAG.

Backpropagation is a graph traversal

A neural network is a DAG of primitive operations. Autograd frameworks build that DAG, topologically sort it, evaluate forward, then walk the reverse order applying the chain rule — reverse-mode automatic differentiation.

So the topological sort we obtain free from DFS is literally the scheduling backbone of PyTorch and TensorFlow. We formalise this in Part 3.

Choosing between them

The choice is about what you must discover, not speed — both are Θ(V+E).

Take BFS when hop-distance or layering matters: shortest paths, GNN receptive fields, level-order processing.

Take DFS when structure matters: ordering, cycles, connectivity, articulation.

Memory can decide too. On a bushy graph BFS's frontier explodes; on a long graph DFS's stack does. The shape of the data picks the traversal.

Placement tip

Bidirectional BFS meets in the middle and cuts the search from O(bd) to O(bd/2) — a strong answer for large-graph shortest-path questions.

Minimum Spanning Trees

Connect every vertex at the least total cost — a rare case where a greedy algorithm is provably optimal, resting on one elegant theorem.

MST problem      Cut property      Prim      Kruskal & union-find
22
Minimum spanning trees
The MST problem, stated precisely
  • Input - a connected, undirected, weighted graph G = (V, E) with w : E → ℝ.
  • Output - a spanning tree T ⊆ E of minimum total weight.
  • Edge count - every spanning tree has exactly |V| − 1 edges.
  • Acyclic - an MST has no cycle: any cycle edge could be deleted, keeping connectivity while lowering cost.
  • Not unique - ties in weight admit several MSTs; the weight is unique.
  • Cut-optimality - if all weights are distinct, the MST is unique.
w(T)= ∑(u,v)∈T w(u,v)  → min

Minimum spanning trees
The cut property: the theorem that makes greed provably correct
  • Cut (S, V−S) - a partition of V into two non-empty sets.
  • Respects A - no edge of A crosses the cut.
  • Light edge - a minimum-weight edge crossing the cut.

Theorem

Let A be a subset of some MST, let (S, V−S) be a cut respecting A, and let (u,v) be a light edge crossing it. Then A ∪ {(u,v)} is also a subset of some MST — i.e. (u,v) is safe for A.

w(T′) = w(T) − w(x,y) + w(u,v) ≤ w(T)

Proof (exchange argument)

Let T be an MST containing A. If (u,v) ∈ T we are done, so assume not.

Adding (u,v) to T creates a unique cycle. That cycle must cross the cut a second time, at some edge (x,y). Since (u,v) is light, w(u,v) ≤ w(x,y).

Set T′ = T − {(x,y)} ∪ {(u,v)}. Removing (x,y) splits T into two components which (u,v) reconnects, so T′ is a spanning tree with w(T′) ≤ w(T). As T is minimum, w(T′) = w(T) and T′ is an MST.

The cut respects A, so (x,y) ∉ A; hence A ∪ {(u,v)} ⊆ T′. ∎

Placement tip

Both Prim and Kruskal are corollaries of this one theorem. Saying so — rather than reciting two procedures — is what distinguishes a strong answer.

Prim and Kruskal: two disciplined ways to invoke the cut property
import heapq
def prim(g, root):
    """O(E log V). Lazy deletion (heapq has no decrease-key)."""
    seen, total, mst = {root}, 0, []
    pq = [(w, root, v) for v, w in g.neighbours(root)]
    heapq.heapify(pq)
    while pq and len(seen) < len(g):
        w, u, v = heapq.heappop(pq)
        if v in seen: continue          # stale entry
        seen.add(v); mst.append((u,v,w)); total += w
        for nx, wt in g.neighbours(v):
            if nx not in seen: heapq.heappush(pq,(wt,v,nx))
    return total, mst

class DSU:                              # union by rank + path compression
    def __init__(s,n): s.p=list(range(n)); s.r=[0]*n
    def find(s,x):
        while s.p[x]!=x: s.p[x]=s.p[s.p[x]]; x=s.p[x]
        return x
    def union(s,a,b):
        a,b=s.find(a),s.find(b)
        if a==b: return False              # would form a cycle
        if s.r[a]<s.r[b]: a,b=b,a
        s.p[b]=a; s.r[a]+= s.r[a]==s.r[b]; return True

def kruskal(n, edges):                   # edges: (w,u,v)
    d,mst,tot = DSU(n),[],0
    for w,u,v in sorted(edges):            # O(E log E) - dominates
        if d.union(u,v): mst.append((u,v,w)); tot += w
    return tot, mst

Same theorem, different cut

Prim takes S = the current tree's vertices. Kruskal's cut is induced by the two components an edge would join. Both always add a light edge across a respecting cut.

Union-find with rank + path compression runs in O(E·α(V)); α is the inverse Ackermann function, ≤ 4 for any n in the physical universe.
